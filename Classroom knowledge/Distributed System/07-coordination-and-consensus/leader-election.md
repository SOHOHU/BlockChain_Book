# 领导者选举

## 📌 问题

**需求**：从一组进程中选出一个作为协调者

### 应用场景

- 分布式锁管理
- 集群主节点选举
- 分布式事务协调器

## 🔧 算法

### 1. Bully算法

**假设**：每个进程有唯一ID，ID最大的成为leader

**流程**：
```
进程P发现leader失效:
1. 向所有ID>P的进程发送ELECTION消息
2. 如果无响应，P成为leader
3. 如果收到响应（OK），等待COORDINATOR消息
4. 超时则重新选举
```

**示例**：
```
进程：P1(ID=1), P2(ID=2), P3(ID=3), P4(ID=4)
P4是leader，P4崩溃

P2发起选举:
- 发送ELECTION给P3, P4
- P3响应OK
- P3向P4发送ELECTION（无响应）
- P3成为新leader，广播COORDINATOR
```

**优点**：✅ 快速
**缺点**：❌ 消息开销大

### 2. Ring算法

**流程**：
```
1. 发现leader失效，发起ELECTION消息
2. 消息沿环传递，每个进程添加自己的ID
3. 消息回到发起者，选择ID最大的
4. 广播新leader
```

**优点**：✅ 消息开销可控
**缺点**：❌ 较慢

### 3. Raft选举

**流程**：
```
1. 超时后成为candidate
2. 增加term，投票给自己
3. 请求其他节点投票
4. 获得多数票成为leader
5. 定期发送心跳维持领导地位
```

**特点**：
- 随机化超时避免冲突
- 保证最多一个leader per term

## 🔑 关键要点

1. **选举**：从多个进程中选出协调者
2. **算法**：Bully、Ring、Raft
3. **挑战**：网络分区、脑裂问题
