# NFS架构与实现

## 📌 NFS特点

1. **对称架构**：每台计算机既可以是客户端也可以是服务器
2. **操作系统独立**：跨平台支持
3. **无状态服务器**：简化容错

## 🏗️ NFS架构

### 虚拟文件系统（VFS）

```
应用程序
    ↓
VFS层（统一接口）
    ↓
 ┌──┴──┐
本地FS  NFS客户端 ──网络──> NFS服务器
                              ↓
                           本地FS
```

### 文件句柄

**组成**：
- 文件系统标识符（唯一）
- 文件i-node号
- i-node生成号

```
文件句柄 = [FS_ID, i-node, generation]
```

## 🔧 NFS操作

| 操作 | 参数 | 返回值 |
|------|------|--------|
| lookup | dirfh, name | fh, attr |
| create | dirfh, name, attr | newfh, attr |
| read | fh, offset, count | data, attr |
| write | fh, offset, count, data | attr |
| remove | dirfh, name | status |

**特点**：所有操作都是**无状态**和**幂等**的

## 🔒 无状态服务器

### 优点

```
1. 简单的故障恢复
   服务器崩溃后重启即可
   无需恢复状态

2. 无需打开/关闭文件
   每个请求独立

3. 支持客户端崩溃恢复
```

### 缺点

```
1. 性能开销
   每次请求携带完整信息

2. 无法优化
   不能利用打开文件的上下文

3. 缓存一致性复杂
```

## 💾 客户端缓存

### 缓存策略

1. **读缓存**：本地缓存读取的数据
2. **写缓存**：延迟写入服务器

### 一致性问题

**问题**：
```
t1: 客户端A读取file（缓存）
t2: 客户端B修改file
t3: 客户端A再次读取file（从缓存？）
```

**NFS解决方案**：

1. **时间戳验证**
   ```python
   if cache_age > 3_seconds:
       check_with_server()
   ```

2. **写时更新**
   ```python
   on_write():
       flush_to_server()
   ```

## 🔑 关键要点

1. **VFS**：提供统一文件系统接口
2. **无状态**：简化容错但影响性能
3. **客户端缓存**：提高性能但需要一致性机制
