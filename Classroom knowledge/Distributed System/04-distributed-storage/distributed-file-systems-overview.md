# 分布式文件系统概述

## 📌 什么是分布式文件系统？

**分布式文件系统（Distributed File System, DFS）**：允许多个客户端通过网络访问存储在多个服务器上的文件。

### 基本架构

```
┌──────┐  ┌──────┐  ┌──────┐
│客户端1│ │客户端2│ │客户端3│
└───┬──┘  └───┬──┘  └───┬──┘
    │         │         │
    └─────────┼─────────┘
              │ 网络
    ┌─────────┼─────────┐
    │         │         │
┌───▼──┐  ┌───▼──┐  ┌───▼──┐
│文件  │  │文件  │  │文件  │
│服务器1│ │服务器2│ │服务器3│
└──────┘  └──────┘  └──────┘
```

## 🎯 设计目标

### 1. 透明性

**访问透明性**：
- 客户端以相同方式访问本地和远程文件
- 隐藏网络细节

**位置透明性**：
- 文件名不揭示物理位置
- `/home/alice/file.txt`可能在任何服务器

**迁移透明性**：
- 文件移动不影响访问
- 路径保持不变

### 2. 并发访问

**场景**：
```
时间  客户端A          客户端B
t1    read(file)      
t2                    write(file)
t3    read(file)      
```

**问题**：如何保证一致性？

**解决方案**：
- 文件锁
- 版本控制
- 事务支持

### 3. 性能

**关键指标**：
- 吞吐量
- 延迟
- 可扩展性

**优化技术**：
- 客户端缓存
- 数据复制
- 负载均衡

### 4. 容错性

**故障类型**：
- 服务器崩溃
- 网络分区
- 磁盘故障

**容错机制**：
- 数据复制
- 自动故障转移
- 检查点和恢复

## 🔄 文件服务模型

### 1. 上传/下载模型

**流程**：
```
1. 客户端下载整个文件
2. 本地修改
3. 上传整个文件到服务器

客户端           服务器
  │               │
  │──下载文件────>│
  │<─ 文件内容 ───│
  │               │
(本地编辑)
  │               │
  │──上传文件────>│
  │<─ 确认 ───────│
```

**优点**：
- ✅ 简单
- ✅ 本地访问快

**缺点**：
- ❌ 并发控制困难
- ❌ 大文件传输慢
- ❌ 版本冲突

### 2. 远程访问模型

**流程**：
```
直接在服务器上操作文件

客户端           服务器
  │               │
  │──read(offset)─>│
  │<─ data ───────│
  │               │
  │──write(offset,data)─>│
  │<─ ack ─────────│
```

**优点**：
- ✅ 易于并发控制
- ✅ 一致性好
- ✅ 适合小操作

**缺点**：
- ❌ 网络开销大
- ❌ 每次操作都需要通信

### 3. 混合模型

**结合两者优点**：
```
- 客户端缓存常用文件
- 写时更新服务器
- 缓存一致性协议
```

## 🔒 一致性模型

### 1. UNIX语义

**特点**：
- 写操作立即对所有进程可见
- 文件共享有严格的时间顺序

```python
# 进程A
fd = open("file")
write(fd, "A")

# 进程B（立即可见）
fd = open("file")
data = read(fd)  # 读到 "A"
```

**优点**：强一致性
**缺点**：性能开销大

### 2. 会话语义

**特点**：
- 关闭文件时才对其他进程可见
- 更改在会话期间私有

```python
# 进程A
fd = open("file")
write(fd, "A")
close(fd)  # 此时才对B可见

# 进程B
fd = open("file")
data = read(fd)  # 现在能读到 "A"
```

**优点**：减少网络通信
**缺点**：弱一致性

### 3. 不可变文件语义

**特点**：
- 文件创建后不可修改
- 新版本替换旧版本

```python
# 创建文件
create("file", data)

# 不能修改，只能替换
create("file", new_data)  # 新版本
```

**优点**：简化并发控制
**缺点**：灵活性低

## 📊 NFS概述

**NFS（Network File System）**：Sun公司开发的经典DFS

### 特点

1. **无状态服务器**
2. **客户端缓存**
3. **UNIX语义（尽力而为）**

### 架构

```
客户端                    服务器
┌──────────┐            ┌──────────┐
│应用程序   │            │应用程序   │
├──────────┤            ├──────────┤
│虚拟文件   │            │虚拟文件   │
│系统(VFS) │            │系统(VFS) │
├─────┬────┤            ├─────┬────┤
│本地 │NFS │            │本地 │NFS │
│文件 │客户│<─ 网络 ───>│文件 │服务│
│系统 │端  │            │系统 │器  │
└─────┴────┘            └─────┴────┘
```

## 🔑 关键要点

1. **DFS目标**：透明性、性能、容错性
2. **服务模型**：上传/下载 vs 远程访问
3. **一致性**：强一致性 vs 弱一致性的权衡
4. **NFS**：工业界广泛使用的DFS实现
