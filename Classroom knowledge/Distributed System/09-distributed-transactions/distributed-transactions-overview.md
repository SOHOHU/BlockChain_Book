# 分布式事务概述

## 📌 什么是事务？

**事务（Transaction）**：一组操作作为单一逻辑单元执行

### ACID属性

**A - 原子性（Atomicity）**：
- 全部成功或全部失败
- 不存在部分完成

**C - 一致性（Consistency）**：
- 事务前后数据一致
- 满足完整性约束

**I - 隔离性（Isolation）**：
- 并发事务互不干扰
- 看起来像串行执行

**D - 持久性（Durability）**：
- 提交后永久保存
- 崩溃后可恢复

## 🌐 分布式事务

**定义**：跨多个节点的事务

### 示例：银行转账

```
事务：Alice转账100元给Bob

操作：
1. 从Alice账户扣100元（服务器A）
2. 向Bob账户加100元（服务器B）

要求：原子性
- 两个操作都成功：提交
- 任一失败：回滚所有操作
```

### 挑战

1. **原子性**：如何保证跨节点原子提交？
2. **并发控制**：如何处理并发事务？
3. **故障处理**：节点/网络故障怎么办？

## 🔑 关键要点

1. **ACID**：事务的四大属性
2. **分布式事务**：跨节点的原子操作
3. **挑战**：原子提交、并发控制、容错
