# 一致性模型

## 📌 一致性谱系

```
强一致性 ────────────────────────────> 弱一致性
  │                                        │
线性一致性 → 顺序一致性 → 因果一致性 → 最终一致性
(Linearizable) (Sequential) (Causal)  (Eventual)
```

## 🔒 强一致性

### 1. 线性一致性（Linearizability）

**定义**：操作看起来是瞬间完成的，且全局有序

```
写(x, 1) ─────────────┐
读(x) ─────────────────┼─ 返回1
                       │
                       └─ 写完成点
```

**特点**：
- 最强一致性
- 性能开销大
- 适合关键数据

### 2. 顺序一致性（Sequential Consistency）

**定义**：所有操作有全局顺序，符合每个进程内的顺序

```
P1: 写(x,1) → 写(y,2)
P2: 读(y) → 读(x)

顺序一致：
可能的全局顺序：写(x,1) → 写(y,2) → 读(y,2) → 读(x,1)
或：写(x,1) → 读(y,0) → 写(y,2) → 读(x,1)
```

## ⚖️ 中等一致性

### 3. 因果一致性（Causal Consistency）

**定义**：有因果关系的操作保持顺序

```
P1: 写(x,1) ─────┐
                 ▼ 因果关系
P2:          读(x,1) → 写(y,2)

保证：所有看到y=2的进程都看到x=1
```

### 4. FIFO一致性

**定义**：每个进程的写操作按顺序被看到

## 🌐 弱一致性

### 5. 最终一致性（Eventual Consistency）

**定义**：如果没有新的更新，最终所有副本会一致

**特点**：
- 高可用性
- 低延迟
- 适合对一致性要求不严格的场景

**示例**：
```
t1: 写(x, 1)到副本A
t2: 读副本B，得到x=0（旧值）
t3: 读副本B，得到x=1（已同步）
```

**应用**：
- DNS
- 社交媒体点赞数
- 购物车

## 📊 CAP定理

**定理**：分布式系统最多满足以下三个中的两个：

- **C（Consistency）**：一致性
- **A（Availability）**：可用性  
- **P（Partition tolerance）**：分区容错性

**实际选择**：
```
CP系统：牺牲可用性保证一致性（银行系统）
AP系统：牺牲一致性保证可用性（社交媒体）

注：P通常是必须的，所以实际是C和A的权衡
```

## 🔑 关键要点

1. **一致性模型**：定义副本行为的规则
2. **强→弱**：一致性越强，性能越差
3. **CAP**：一致性和可用性的权衡
4. **选择**：根据应用需求选择合适模型
