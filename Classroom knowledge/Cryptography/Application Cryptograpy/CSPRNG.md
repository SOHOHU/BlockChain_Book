# 随机性密码学

## 1 随机数概念

* **TRNG（真随机源）**：来自物理噪声（热噪声、放射性衰变、光电噪声等），输出“真随机”位 —— 高熵但通常慢且需要硬件。
* **PRNG（伪随机）**：由确定性算法根据种子产生序列；速度快但可预测（若知道种子/内部状态）。不安全用于密钥。
* **CSPRNG（密码学安全的伪随机）**：用**高熵种子 + 密码学构造**（哈希、HMAC、分组密码、流构造等）产生的伪随机流。目标是**不可预测**且满足不可回溯性，适合生成密钥/nonce/IV 等敏感值。
---

## 2 CSPRNG 的安全性目标（更精确）

一个合格的 CSPRNG 至少应满足：

### 2.1 前向不可预测性 (Forward Secrecy / Next-bit Unpredictability)

**目标：** 确保攻击者不能“预知未来”。

即使攻击者掌握了 CSPRNG **迄今为止所有**的输出序列，他也无法在合理时间内推测出下一个即将生成的随机数（哪怕只是下一个比特位）。 
**实现方式** CSPRNG 算法本身必须基于**单向函数**（例如哈希函数或 HMAC）。单向函数确保了从结果（输出）难以反推过程（下一个输出）。 

### 2.2. 后向不可恢复性 (Backtracking Resistance / Backward Secrecy)

如果攻击者通过某种方式（例如系统漏洞或物理侧信道攻击）**获得了 CSPRNG 当前的内部状态（Internal State）**，他也无法计算或恢复出**在这之前**已经生成并输出的随机数序列。
 **实现策略**  **定期“摧毁”旧状态并用新熵更新（Reseeding）。** CSPRNG 会定期引入新的、高质量的真随机数（熵），与旧状态混合，生成一个全新的、与旧状态在数学上不再相关的内部状态。这切断了新状态与旧历史输出之间的数学联系。 

### 2.3. 长周期与良好统计特性

**目标：** 确保序列在数学上是“够随机”的。

 **长周期**  伪随机数序列终究会重复，但 CSPRNG 的重复周期必须**极长**，通常长到比宇宙的寿命还久。如果周期太短，攻击者可以通过简单地等待周期循环，来预测未来的序列。 
**良好统计特性**  这意味着生成的序列必须通过严格的**统计测试**（例如 NIST 的测试套件）。在统计学上，序列必须表现得像真随机数一样：
    * 0 和 1 的出现频率大致相等。
    * 任意子序列（如 8 个 0 组成的一块）出现的概率符合统计学预测。
 **密码学意义**  统计特性好是**必要条件**，但**非充分条件**。一个通过所有统计测试的 PRNG，如果不满足前两条（不可预测、不可回溯），仍然是不安全的。它只是在**表面上**看起来是随机的。

### 4. 可安全地种子化与再种子 (Seeding / Reseeding)

**目标：** 确保 CSPRNG 的生命周期都能获得充足的能量（熵）。

 **种子化 (Seeding)**  这是 CSPRNG **启动**的过程。必须使用来自 TRNG（真随机数生成器）的、具有足够**熵（Entropy）**的初始值来初始化 CSPRNG 的内部状态。如果种子质量差（熵不足），则内部状态从一开始就是可预测的。 
 **再种子 (Reseeding)**  这是 CSPRNG 在**运行过程中**定期或在特定事件（如检测到熵池被耗尽）后，补充新熵的过程。
    * **作用：**
        1.  **维持抵抗力：** 随着时间推移，攻击者可能会收集足够的输出以尝试反推状态；再种子提供了新的防御层。
        2.  **实现后向不可恢复性：** 如第二点所述，新的熵会“洗掉”旧状态的痕迹，抵抗回溯攻击。


## 3 常见 CSPRNG 构造（直观分类）

为了满足前向不可预测性和后向不可恢复性这两个苛刻的安全要求，密码学安全伪随机数生成器 (CSPRNG) 的设计通常依赖于已证明安全的**密码学原语**。这些构造模式的核心思想都是将少量的真随机数（种子）安全地扩展成大量的、不可预测的伪随机数。

### 3.1. 基于哈希 / HMAC 的 DRBG (Hash-DRBG / HMAC-DRBG)

这种构造方式的核心在于利用**哈希函数**的强大**单向性**。哈希函数是密码学中最可靠的工具之一，它保证了从输出无法有效反推输入。

在 Hash-DRBG 或 HMAC-DRBG 中，核心思路是利用哈希或 HMAC（带密钥的哈希）作为一个**状态更新和输出函数**。系统维护一个**内部状态 $V$** 和一个**密钥 $K$**（在 HMAC-DRBG 中）。每当需要新的随机数时，就使用一个迭代公式，例如 $V_{\text{new}} = \text{HMAC}(K, V_{\text{old}})$，来生成下一组随机数，并同时更新内部状态。

这种方法的优点是：它基于成熟、经过长期分析的哈希算法（如 SHA-256），其安全性有充分的理论支撑，并且相对容易分析和正确实现。

### 3.2. 基于分组密码的 DRBG (CTR-DRBG / AES-CTR)

这种构造模式依赖于成熟的**分组密码（Block Cipher）**，如 AES（高级加密标准）。其核心思想是模仿**计数器模式 (CTR)** 的工作方式来生成密钥流，因此常被称为 CTR-DRBG。

在这个模式中，分组密码的**密钥 $K$** 被用作 CSPRNG 的内部状态，而加密算法（例如 $\text{AES}_K(\text{Counter})$）被用来加密一个不断递增的**计数器**。每次加密的输出块都被用作新的伪随机数。

这种构造方式的突出优点是**速度极快**。许多现代 CPU 都配备了 AES 硬件加速指令（如 Intel 的 AES-NI），使得分组密码 DRBG 在性能上有巨大优势，特别适用于需要高速随机数生成的环境。

### 3.3. 基于流密码或流构造（如 ChaCha20）

这种模式利用了专为**高速、常时**（Constant-Time，抵抗时序攻击）设计的**流密码**，其中 ChaCha20 是一个现代的流行选择。

流密码本身就是设计用于将一个短密钥和一个初始向量（Nonce）扩展成一个长、随机的密钥流。在构造 CSPRNG 时，**种子**被用作 ChaCha20 的**密钥**和**初始计数器**。通过运行 ChaCha20 算法并递增内部计数器，可以高效地、安全地生成大量的伪随机数。

由于 ChaCha20 结构简洁且设计优良，它在软件中的实现非常高效，并且天然具有防止侧信道攻击（如时序攻击）的特性，使其在移动设备和各种网络应用中日益普及。

### 3.4. 混合模式（工程实用性）

在实际的工程应用中，为了达到最高的安全性，CSPRNG 很少只依赖单一的来源。**混合模式**是工业界普遍采用的方案。

在这种模式下，系统首先从多个独立的、不可预测的**熵源**中收集真随机数，这些熵源可能包括硬件 TRNG、CPU 时钟的微小噪声、用户输入事件、网络事件等。然后，系统使用像 KDF（密钥导出函数）或 HMAC 这样的密码学工具，将这些不同来源的熵**安全地混合**起来，生成一个高质量的、高熵的**主种子**。

最后，这个主种子被用来启动一个高性能的**确定性随机比特生成器 (DRBG)**（如前面提到的 Hash-DRBG 或 CTR-DRBG），以便快速、持续地为应用程序提供大量的安全随机数。这种多源混合的策略大大提高了生成器的鲁棒性，即使某个单一熵源失效或被攻破，整体的安全随机性仍然得以维持。
