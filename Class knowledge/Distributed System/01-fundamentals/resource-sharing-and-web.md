# 资源共享与Web示例

## 📌 资源共享：分布式系统的主要动机

**资源共享（Resource Sharing）**是构建分布式系统的主要动机和目标。

## 🎯 资源的类型

资源可以以多种形式存在：

### 1. 信息资源（Information）
- 文本、图片、音频、视频
- 新闻
- 电子邮件
- 网页内容
- 数据库数据

### 2. 硬件资源（Hardware）
- 计算能力（CPU、GPU）
- 存储空间（磁盘、内存）
- 摄像头
- 打印机
- 传感器设备

### 3. 软件资源（Software）
- 系统软件（操作系统、数据库管理系统）
- 应用程序（办公软件、开发工具）
- 库和框架
- API服务

## 💰 资源共享的好处

1. **节省成本**
   - 避免重复购买硬件
   - 减少软件许可费用
   - 共享基础设施

2. **节省人力**
   - 集中式管理和维护
   - 减少重复劳动
   - 专业化分工

3. **提高效率**
   - 按需访问资源
   - 负载均衡
   - 资源利用率最大化

## 🔧 资源共享的机制：服务

### 服务模型

**问题**：资源如何共享？  
**答案**：通过服务（Services）

#### 核心概念

**服务（Service）**：
- 计算机系统的一个独立部分
- 提供对所管理资源的访问
- 例如：文件的读/写/删除操作

**服务器（Server）**：
- 管理资源的进程
- 例如：Web服务器、数据库服务器

**客户端（Client）**：
- 请求访问资源的进程
- 例如：Web浏览器、数据库客户端

### 工作流程

```
1. 客户端发送请求给服务器
2. 服务器接受请求
3. 服务器执行服务（操作资源）
4. 服务器将响应返回给客户端

┌────────┐  请求   ┌────────┐
│ Client │ ─────> │ Server │
│        │ <───── │        │
└────────┘  响应   └────────┘
```

**请求和响应以消息（Messages）形式发送**

### 远程调用（Remote Invocation）

**定义**：从客户端发送请求到接收服务器响应的完整交互过程

```
时间线：
Client: │─发送请求─│───等待───│─接收响应─│
                    ↓         ↑
Server:         │─接收请求─处理─发送响应─│
```

### Web请求示例

#### 示例1：搜索请求

```http
客户端: http://www.google.com/search?q=computer

1. 浏览器解析URL
2. DNS查询获取IP地址
3. 建立TCP连接
4. 发送HTTP GET请求
5. 服务器处理搜索
6. 返回HTML结果
7. 浏览器渲染页面
```

#### 示例2：访问主页

```http
客户端: http://www.ntu.edu.sg/

1. 浏览器请求主页
2. 服务器从文件系统读取index.html
3. 返回HTML内容
4. 浏览器显示页面
```

#### 示例3：访问特定资源

```http
客户端: http://www.w3.org/Protocols/Activity.html

服务器: www.w3.org
文件系统路径: /Protocols/Activity.html
```

### Web的关键组件

#### 1. 浏览器（Browser）- 客户端

**功能**：
- 发送HTTP请求
- 接收并解析HTTP响应
- 渲染HTML、CSS、JavaScript
- 管理Cookie和缓存

**示例**：
- Chrome
- Firefox
- Safari
- Edge

#### 2. Web服务器（Web Server）- 服务器

**功能**：
- 监听HTTP请求
- 处理请求（静态文件或动态内容）
- 访问后端文件系统或数据库
- 返回HTTP响应

**示例**：
- Apache
- Nginx
- IIS
- Tomcat

#### 3. 文件系统（File System）

**功能**：
- 存储网页文件
- 存储静态资源（图片、CSS、JS）
- 可能是分布式文件系统

### HTTP协议：Web的通信协议

#### HTTP请求结构

```http
GET /search?q=computer HTTP/1.1
Host: www.google.com
User-Agent: Mozilla/5.0
Accept: text/html
```

**组成部分**：
- **请求行**：方法 + URL + 协议版本
- **请求头**：提供附加信息
- **请求体**（可选）：POST数据

#### HTTP响应结构

```http
HTTP/1.1 200 OK
Content-Type: text/html
Content-Length: 1234

<html>
  <body>
    <h1>Search Results</h1>
    ...
  </body>
</html>
```

**组成部分**：
- **状态行**：协议版本 + 状态码 + 状态消息
- **响应头**：内容类型、长度等
- **响应体**：实际内容（HTML、JSON等）

#### HTTP方法

| 方法 | 用途 | 示例 |
|------|------|------|
| GET | 获取资源 | 访问网页 |
| POST | 提交数据 | 表单提交 |
| PUT | 更新资源 | 上传文件 |
| DELETE | 删除资源 | 删除记录 |
| HEAD | 获取元数据 | 检查资源是否存在 |

### Web作为分布式系统的特点

#### 优势

1. **全球规模**
   - 数以亿计的用户
   - 分布在世界各地

2. **资源丰富**
   - 海量信息资源
   - 多样化内容

3. **易于访问**
   - 统一的URL定位
   - 标准化协议（HTTP）

4. **可扩展**
   - 易于添加新服务器
   - CDN加速

#### 体现的分布式特性

1. **客户端-服务器架构**
   - 清晰的角色划分
   - 浏览器 vs Web服务器

2. **异构性**
   - 不同操作系统的服务器
   - 不同的浏览器
   - HTTP协议实现互操作

3. **透明性**
   - 位置透明：URL隐藏服务器物理位置
   - 访问透明：相同方式访问不同服务器

4. **缓存和复制**
   - 浏览器缓存
   - 代理服务器缓存
   - CDN内容分发网络

5. **可扩展性**
   - 负载均衡器分散流量
   - 多个Web服务器协同工作

## 🔄 Web请求的完整流程

### 详细步骤

```
1. 用户在浏览器输入URL: http://www.example.com/page.html

2. 浏览器解析URL
   - 协议: http
   - 主机: www.example.com
   - 路径: /page.html

3. DNS解析
   Browser → DNS Server: "www.example.com的IP是什么?"
   DNS Server → Browser: "93.184.216.34"

4. 建立TCP连接
   Browser → Server: SYN (同步)
   Server → Browser: SYN-ACK (同步-确认)
   Browser → Server: ACK (确认)

5. 发送HTTP请求
   GET /page.html HTTP/1.1
   Host: www.example.com

6. 服务器处理
   - 查找文件系统中的/page.html
   - 读取文件内容
   - 构建HTTP响应

7. 发送HTTP响应
   HTTP/1.1 200 OK
   Content-Type: text/html
   [HTML内容]

8. 浏览器渲染
   - 解析HTML
   - 下载CSS、JavaScript、图片
   - 渲染页面

9. 关闭连接（或保持连接用于后续请求）
```

## 🎯 现代Web的演进

### 静态Web → 动态Web

**静态Web**：
```
浏览器 → Web服务器 → 文件系统
           ↓
      返回静态HTML
```

**动态Web**：
```
浏览器 → Web服务器 → 应用服务器 → 数据库
           ↓            ↓           ↓
      返回动态生成的HTML
```

### Web 2.0 和现代架构

**特点**：
- RESTful API
- 前后端分离
- 微服务架构
- WebSocket实时通信
- 单页应用（SPA）

## 🔑 关键要点

1. **资源共享**是分布式系统的主要动机
2. **服务模型**：通过客户端-服务器交互实现资源共享

4. **HTTP协议**支持Web的资源访问
5. **现代Web**：从静态到动态，从单体到微服务
