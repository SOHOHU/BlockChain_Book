# 复制的目的与挑战

## 📌 为什么需要复制？

### 1. 容错性（Fault Tolerance）

```
无复制：服务器崩溃→服务不可用
有复制：主服务器崩溃→切换到备份服务器
```

### 2. 性能

**读性能提升**：
```
无复制：所有读请求到单一服务器
有复制：读请求分散到多个副本
```

**低延迟**：
```
用户访问地理上最近的副本
```

### 3. 可扩展性

```
横向扩展：添加更多副本
支持更多并发请求
```

## 🚧 挑战

### 一致性问题

**问题**：
```
时刻t1：客户端A写入副本1（x=1）
时刻t2：客户端B读取副本2（x=0？）
```

**一致性级别**：
- 强一致性：所有副本立即一致
- 弱一致性：最终一致，但有延迟
- 最终一致性：保证最终收敛

## 🔑 关键要点

1. **复制目的**：容错、性能、可扩展性
2. **核心挑战**：保持副本一致性
3. **权衡**：一致性 vs 可用性 vs 性能
