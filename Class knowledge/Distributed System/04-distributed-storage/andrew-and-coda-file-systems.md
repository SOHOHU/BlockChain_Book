# Andrew与Coda文件系统

## 📌 AFS（Andrew File System）

### 设计目标

1. **可扩展性**：支持大量客户端
2. **性能**：减少服务器负载
3. **透明性**：用户无感知

### 核心思想：全文件缓存

```
客户端缓存整个文件（而非块）
本地访问速度快
减少服务器负载
```

### 回调机制

```
1. 客户端打开文件时，服务器记录回调承诺
2. 其他客户端修改文件时，服务器通知所有缓存该文件的客户端
3. 客户端使缓存失效
```

**优点**：
- ✅ 减少服务器负载（无需轮询）
- ✅ 强一致性

## 📌 Coda文件系统

### 关键特性：断开操作

**场景**：移动设备，网络不稳定

**解决方案**：
```
1. 本地缓存关键文件
2. 断网时继续工作
3. 重新连接时同步
```

### 冲突检测与解决

```
客户端A（离线）: 修改file.txt
客户端B（离线）: 修改file.txt

重新连接后：检测到冲突
- 自动合并（如果可能）
- 或提示用户手动解决
```

## 🔑 关键要点

1. **AFS**：全文件缓存 + 回调机制
2. **Coda**：支持断开操作
3. **权衡**：可用性 vs 一致性
