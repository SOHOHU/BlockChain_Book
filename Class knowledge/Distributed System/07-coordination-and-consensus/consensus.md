# 共识问题

## 📌 什么是共识？

**共识（Consensus）**：让所有进程就某个值达成一致

### 要求

1. **终止性（Termination）**：所有进程最终决定一个值
2. **一致性（Agreement）**：所有进程决定相同的值
3. **完整性（Integrity）**：决定的值是某个进程提议的
4. **有效性（Validity）**：如果所有进程提议相同值，则必须决定该值

## 🚫 FLP不可能性

**FLP定理**：在异步系统中，即使只有一个进程可能崩溃，也不存在确定性共识算法

**启示**：
- 需要同步假设
- 或使用概率算法
- 或牺牲终止性

## 🔧 实用共识算法

### Paxos

**角色**：
- Proposer：提议值
- Acceptor：接受提议
- Learner：学习决定的值

**流程（简化）**：
```
Phase 1 (Prepare):
- Proposer发送准备请求（编号n）
- Acceptor承诺不接受编号<n的提议

Phase 2 (Accept):
- Proposer发送接受请求（编号n，值v）
- Acceptor接受提议
- 多数Acceptor接受则达成共识
```

### Raft

**特点**：更易理解的Paxos替代

**核心机制**：
1. Leader选举
2. 日志复制
3. 安全性保证

**日志复制**：
```
1. Client发送命令给Leader
2. Leader追加到本地日志
3. Leader复制日志到Followers
4. 多数确认后提交
5. 通知Followers提交
```

## 🔑 关键要点

1. **共识**：所有进程就值达成一致
2. **FLP**：异步系统无确定性解
3. **实用算法**：Paxos、Raft
