# BD 渠道、竞争格局、术语与学习路线

## 1. BD 的基本概念

### 1.1 定义
在支付行业，BD 连接需求与供给：撮合客户与通道/合作方，协调价格、SLA 与合规边界。简单讲，就是把"想要流量的"和"能提供通道的"对上，并让它长期跑得稳。

### 1.2 为什么重要
- 客户结构决定收入是否稳得住
- 渠道结构影响服务能不能扛波动
- 合同与合规边界，框住了业务的玩法

一个常见感受：
- 客户全在一个赛道，风一吹就一起波动；
- 通道只有一条，限额或政策一变就"卡脖子"。

## 2. 竞争与市场趋势

### 2.1 市场焦点变化
- 焦点从"谁更便宜"变成"谁更稳、谁的合规与技术更靠谱"
- 行业在做风控数据化、以及持牌整合
这些变化更能决定留存与复购。

## 3. 支付行业的"内卷"现象

### 3.1 费率竞争白热化
业内普遍观察到几个关键现象：
- 大客户（月流水500万美金）可以谈到千一费率（0.1%）
- 但千一费率下，500万流水只能赚5000美金，基本不赚钱
- 大客户拿一家报价去压另一家，形成恶性循环

例子（大客户价差被无限放大）：
- 客户A月流水约500万美元，谈到0.1%。名义收入=500万×0.1%=5000美金。
- 同期真实成本包含：中转行费用、失败退回重提、合规抽检、汇损与做市点差、人工运营值守等，合计很容易>5000。
- 结果：名义“赚到”的5000，被隐性成本吃掉，甚至出现倒挂；为留住客户继续压价，形成“越做越薄”的循环。

对比（腰部客户更可持续）：
- 客户B月流水约100万美元，费率0.3%+每笔固定费2美元，平均单笔2000美元/500笔。
- 费率收入=100万×0.3%=3000美元；固定费=2×500=1000美元；总收入≈4000美元。
- 成本侧（失败重提/汇损/人工）占比更低，单位收入“健康度”显著高于大客户的0.1%。

### 3.2 服务与价格的矛盾
- "千一宁愿不做，都不赚钱，有啥服务的"
- 过度压价导致服务质量下降，BD离职率极高
- 万里汇BD"第一批是全换了"，人员流动性最高

例子（低价换来高波动）：
- 商家C拿到极低费率，但遇到两种典型问题：
  1) 月末通道限额收紧，出款排队，交付SLA失准；
  2) 小币种清算不稳，失败率升高、退回率抬头，运营投诉激增。
- 当客服/风控/合规的人手随之紧张且流动性上升，响应时效进一步变差，形成“低价—不稳—投诉—更不稳”的负反馈。

### 3.3 传统支付公司的Web3布局差异
- 最快的和最慢的差距超过1年
- 杭州某家比上海某家快半年
- 有些公司"看不懂web3也不敢做"，有些"被政府关照不敢做"

例子（时间差=胜负手）：
- 公司X提前6个月打通“稳定币收款→合规换汇→本地清算”的闭环：
  - 主体与牌照路径明确（如HK主体+相应牌照/合作安排）；
  - 产品侧支持USDT/USDC多链入金，内部有清分台账；
  - 银行伙伴明确白名单行业；
  - 风控规则支持链上地址画像与名单协同。
- 公司Y仍停留在“仅法币收款”的方案阶段。
- 结果：同一批客户招投标，X拿下加密相关场景，Y的报价即使更低，也因“能力缺口”被提前排除。

### 3.4 为什么会出现"内卷"
- 同质化竞争：大家都在做同样的通道聚合
- 大客户议价能力强：流水可以随时切换
- 监管门槛提高：合规成本上升，但差异化不明显
- 技术门槛降低：API对接相对容易，护城河不深

例子（同质化+低迁移成本）：
- 绝大多数方案都提供：多通道聚合、结算周期可选、基础风控、对账与Webhook回调。
- 客户迁移成本低：更换API Key/回调地址+对账适配，1-2周内可以完成灰度切换。
- 当“产品看起来都一样”且“切换也不难”时，议价就被放大为核心变量，价格战难以避免。

## 4. 常用术语

### 4.1 基础概念
- **On-Ramp / Off-Ramp**：法币与链上资产的双向转换。
  简单说就是"进出"：On-Ramp 是拿人民币买USDC，Off-Ramp 是把USDC换成美元。这就像机场换汇，但换的是"数字钱"。为什么重要？因为链上的应用越来越多，但现实世界还是用法币，所以这个"桥"就特别关键。比如你收到USDC广告费，但供应商只要美元，那就得先Off-Ramp。

- **VA / POBO**：虚拟账户与代付。
  VA就是"虚拟银行卡号"，每个客户一个，来款就知道是谁的。POBO是"代客户付钱"，平台统一帮大家往外打钱。为什么有用？想象一下，100个商家都给你打钱，如果没有VA，你根本分不清谁是谁；如果没有POBO，每个商家都要自己开银行账户，太麻烦了。

- **PSP / VASP**：支付与虚拟资产服务提供者。
  PSP是传统支付公司，管法币的；VASP是管加密货币的。现在很多业务需要两边都懂，所以经常要合作。比如一家做跨境收款的PSP，找一家合规的VASP，就能提供"USDT收款+本地法币提现"的服务。

### 4.2 合规相关
- **KYC/KYB、PEP、AML**：身份核验与反洗钱相关。
  KYC是查个人，KYB是查企业，PEP是查政治敏感人物，AML是整套反洗钱规则。这些听起来很枯燥，但实际很重要——决定你能收多少钱、多久收一次。比如企业没补齐"最终受益人"的材料，银行就会把你的额度卡得很紧，补齐了才能放开。

### 4.3 技术要素
- **SLA、API/Webhook**：服务与技术对接要素。
  SLA就是"服务承诺"，比如"99.9%可用，2小时内到账"。API是系统之间"说话"的接口，Webhook是"有消息就通知你"的机制。为什么重要？因为客户最怕的就是"钱不知道到没到"，所以实时反馈特别关键。如果Webhook延迟了，商家那边显示"处理中"，客服电话就炸了。

- **SWIFT/SEPA/ACH/FPS**：清算网络。
  这些是不同地区的"银行高速公路"：SWIFT是国际的，SEPA是欧洲的，ACH是美国的，FPS是香港的。每条路的"过路费"和"限速"都不一样。比如欧元区内走SEPA几乎免费，但跨境SWIFT就贵很多，还慢。

### 4.4 计费方式
- **千一/千二、固定费**：计费方式。
  "千一"就是0.1%，"千二"是0.2%。固定费就是每笔收固定钱，不管金额大小。为什么这样设计？因为小额交易按比例收太贵，大额交易按固定费收太便宜。比如200美元的交易，千一才收0.2美元，但固定费可能收2美元；20万美元的交易，千一收200美元，但固定费还是2美元。

### 4.5 相关技术
- **RWA、稳定币、DEX、智能合约**：见相关笔记。
  RWA是把现实世界的资产"上链"，比如把房租收益做成代币。稳定币就是"不会大起大落的加密货币"，像USDC。DEX是去中心化交易所，不用注册就能交易。智能合约是"自动执行的合同"。这些技术让链上世界更实用，比如用稳定币转账比银行便宜，用RWA可以提前拿到现金流。
