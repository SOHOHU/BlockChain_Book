## ZK-Rollup：一种基于ZK的L2扩展方案

---

### 1、什么是Rollup？

在开始介绍ZK-Rollup之前，我们需要先介绍一下Rollup。


在区块链中，**Rollup** 是一种 **Layer 2（第二层）扩展解决方案**。它的核心目标是**提高主区块链（Layer 1, L1，例如以太坊）的交易吞吐量，同时降低交易费用**，而不牺牲安全性。我们想象一下，当今每时每刻都在进行者关于ETH的交易，如果不存在Rollup方案，这些交易将会全部在ETH的L1上进行。而我们同时知道，L1的吞吐量是及其有限的，如果让L1短时间内出来上万个交易，gas费早就爆炸啦！！

所以我们可以把 Rollup 理解为一个高效的“批量处理器”。

Rollup 的工作方式可以概括为以下三个步骤：

1.  **链下执行（Off-Chain Execution）：** Rollup 不在拥堵的主链（L1）上处理用户交易，而是在自己的 **Layer 2 网络**上执行交易。
2.  **批量处理（Batching/Rolling Up）：** Rollup 运营商将数千笔 L2 交易打包成一个**巨大的批次**。
3.  **链上提交（On-Chain Submission）：** Rollup 只将这个批次的**压缩数据**（包括必要的状态更改和有效性证明）作为一个单一交易提交到 L1 主链上的一个智能合约。

尽管交易是在链下处理的，Rollup 依然将关键数据提交回 L1，并依赖 L1 的共识机制来保证其 L2 状态的最终有效性和安全性。

当前Rollup 主要分为两种类型，它们使用不同的机制来证明链下交易的有效性：

| 特征 | **1. ZK-Rollups (Zero-Knowledge Rollups) 零知识汇总** | **2. Optimistic Rollups (乐观汇总)** |
| :--- | :--- | :--- |
| **有效性证明机制** | **有效性证明（Validity Proofs）**：提交批次时，必须同时提交一个**零知识证明 (ZKP)**，用数学方法证明交易有效。 | **欺诈证明（Fraud Proofs）**：**乐观地**假设所有交易有效。只有当有人发现无效交易时，才会在一个挑战期内提交欺诈证明。 |
| **最终确定性** | **快速：** 因为 L1 合约立即验证 ZKP，一旦验证通过，状态就立刻确定。 | **延迟：** 存在一个**挑战期/争议期**（通常为 7 天），在此期间内用户才能安全地将资产提取回 L1。 |
| **计算复杂性** | 链下生成 ZKP **计算成本高**，但 L1 验证**成本低且速度快**。 | L2 计算简单，但 L1 验证**涉及挑战期**。 |

这次我们将要详细讨论ZK-Rollup

### 2. 核心机制：状态转换和零知识证明 (ZKP)

这是 ZK-Rollups 最核心的工作方式，当然是ZKP。ZKP的基本原理我们不再赘述，但是我们应该理解ZKP是怎么在ZK-Rollup中应用的。

我们知道以太坊主网（EVM）是用状态转换来确认交易的。ZK-Rollups 的 Layer 2 (L2) 状态通过一个**默克尔树 (Merkle Tree)** 来表示，其根节点是一个哈希值，称为状态根 (`Root`)。
    * `Root`：表示交易前的 L2 **旧状态**。
    * `Root'`：表示交易后的 L2 **新状态**。
    * **叶子节点（Leaves）**：图中底部的数字（如 $10, 9$）代表 L2 状态树中的账户或数据点。

ZKP 用来证明**状态转换**（即从 `Root` 到 `Root'` 的过程）是**有效**的，并且是根据 L2 的规则正确执行的。验证者（L1 合约）可以通过验证 ZKP 确认交易的有效性，而**无需重新执行**所有交易或知道交易的具体内容。如果 ZKP 验证失败，则 L1 合约将拒绝这次状态更新，新状态根 (Root') 将不会被存储。这有效地防止了 L2 操作者提交任何无效或欺诈性的状态。
Layer 2 (L2) Rollup 向 Layer 1 (L1) 证明或提交的核心内容，是为了确保 L2 状态的**有效性、最终确定性**和**数据可用性**。

#### 2.1 证明内容：

##### 2.1.1 状态转换的有效性（Proof of Correctness）

L2 必须向 L1 证明，它对 L2 状态的所有更改都是根据预定规则正确执行的。

证明：存在一个**有效的执行过程**，它将 L2 的**旧状态根（Root）**通过批次中的所有交易，正确地转换成了**新状态根（Root'）**。这个证明是**数学上的确凿保证**。 |


##### 2.1.2 状态根的更新（State Commitment）

L2 必须向 L1 提交 L2 状态的加密摘要，以便 L1 能够追踪 L2 的官方“最新”状态。

* **提交内容：** **新状态根（Root'）**。

这个新状态根包含了批次中所有交易执行后的 L2 账户余额、合约存储等最新信息。L1 合约在验证了有效性证明（或挑战期结束后）后，会接受并**存储**这个新的 `Root'`，从而更新 L2 的官方状态。

##### 2.1.3 数据可用性（Data Availability, DA）

Rollup 必须确保所有用户都能够访问到批次中的**所有交易数据**，以便任何人都能重新构造 L2 状态，并在必要时提交欺诈证明或强制提款。

* **提交内容：** **压缩后的交易数据（Compressed Transaction Data）**。
证明了 L2 的交易细节数据已经被发布到了 L1（通常是以**`calldata`** 的形式），这使得 L2 的运营者无法私藏数据，保证了**抗审查性**（用户可以强制提款）和**去中心化**。

#### 2.2 L2和L1交互的底层逻辑

我们接下来来讨论一下 ZK-Rollups 如何继承 L1 安全性。

首先我们需要在 L1 主链上部署有一个 ZK-Rollup 智能合约。提交者将 **ZKP** 和 **新状态根 (`Root'`)** 提交给 L1 合约。L1 合约执行 **ZKP 验证** (`ZKP check`)。如果验证通过，L1 合约会**存储 (`Store`)** 新的状态根 `Root'`，从而正式确定 L2 的新状态。

这个新的状态根 `Root'`会和在L1上进行的交易一样，广播全网节点进行验证，通过验证之后会将区块打包（这些交易依然是打包在L2）

* 状态根的更新需要 L1 上的加密验证通过，确保了 L2 状态的有效性由高度安全的 L1 保证。


### 3. 抗审查性和数据可用性

**ZK-Rollups 中的抗审查性（Censorship Resistance）和数据可用性（Data Availability, DA）**。这两个特性对于任何 Rollup 解决方案来说都至关重要，它们确保了用户资产的安全和 L2 网络的去中心化，也是 L2 能够继承 L1 安全性的关键。

#### 3.1 数据可用性 (Data Availability, DA)

数据可用性是 Rollup 安全模型的基石。

L2 Rollup 的操作者（一般由数据集成器实现）在链下处理交易，然后将摘要提交到 L1。如果操作者是恶意的，他们可能会**扣留**批次中完整的交易数据，只向 L1 提交状态根和证明。如果交易数据不可用，用户将无法知道 L2 的准确状态，也无法证明自己的资产归属，更无法将资产安全地提回到 L1。这就导致了**数据可用性攻击**。

ZK-Rollups 解决这个问题的方法是：

L2 操作者必须将批次中的**所有压缩后的交易数据**作为 **L1 的 `calldata`**（调用数据）提交到 L1 智能合约。否则Rollup无效。由于 L1 区块链的每一个全节点都会存储 `calldata`，这就确保了这些交易数据是**公开、可获取、永久存储**的。

任何人（包括普通用户）都可以通过读取 L1 上的 `calldata` 来重建 L2 的完整状态，从而消除恶意操作者扣留数据的可能性。这样保证Rollup 将计算和存储转移到 L2，但将最关键的**数据可用性**保证放在了最安全的 L1 上。

---

#### 3.2 抗审查性 (Censorship Resistance)

抗审查性是指 L2 上的用户永远能够强制执行其交易（特别是提款），即使 L2 的运营者（Sequencer 或 Prover）拒绝处理他们的请求。

L2 操作者（Sequencer）负责收集和排序 L2 交易。如果一个恶意的操作者故意忽略某个用户的交易，或者阻止某个用户将资产提回到 L1，这就是**审查**。

ZK-Rollups 通过利用 L1 智能合约来提供一个**“后门”或“逃生舱”**机制，以对抗 L2 操作者的审查：

* **强制提款机制（Forced Withdrawal）：**
    1.  如果用户怀疑自己被 L2 操作者审查（例如，提款交易长时间未被打包），用户可以直接在 **L1 上的 Rollup 合约**中提交一个**强制交易 (`forced Tx`)**。
    2.  这个强制交易会触发 L1 合约中的一个特殊逻辑，将用户的提款请求**排队**。
    3.  L2 操作者**必须**在接下来的 L2 批次中包含这个 L1 上排队的强制交易。

如果 L2 操作者拒绝在规定时间内处理 L1 上的强制交易，L1 合约可以采取惩罚措施（如罚没保证金）或启用**紧急模式**，允许用户直接在 L1 上执行提款（前提是数据可用性得到保障）。

通过数据可用性和强制交易机制，ZK-Rollups 确保了用户资产的安全，并保证了在 L2 运营者恶意行为下用户也能安全退出 L2 网络。

### 4 zkSync：通用型 ZK-Rollup 的先驱

**zkSync** 是 Matter Labs 团队开发的一个 ZK-Rollup 协议和网络。它的目标是提供一个**以太坊虚拟机兼容（EVM-compatible）**的 Layer 2 解决方案，同时保留以太坊的去中心化和安全性。

zkSync 经历了多个版本，目前最新版本是 **zkSync Era 2025**。

### zkSync 的核心技术点

1.  **zkEVM (Zero-Knowledge Ethereum Virtual Machine)**
    * **挑战**：以太坊的 EVM 逻辑（尤其是复杂的哈希、循环和 I/O）很难用 ZK 友好的算术电路来高效表示。
    * **zkSync 的方案**：zkSync Era 实现了一个 **zkEVM**，这意味着开发者可以像在以太坊主网上一样，用 **Solidity 语言**编写和部署智能合约。zkEVM 的任务就是将 EVM 的操作码翻译成 **ZK 友好的约束**。
2.  **ZK-SNARKs 的应用**
    * **技术选择**：zkSync 内部使用了类似 **PlonK** 或更先进的 **Boojum**（基于 STARKs 理念的新证明系统）的 ZK 协议。
    * **过程**：它将所有 EVM 操作转化为代数约束，生成一个简洁的证明，证明 EVM 的执行是正确的。
3.  **透明设置**
    * zkSync 正在过渡到使用更透明、抗量子的证明系统（如 Boojum，受到 STARKs 思想的启发），以减少对传统 **Groth16 可信设置**的依赖，增强其长期安全性。
